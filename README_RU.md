# Arena DDS Optimizer (Qt)

Пакетный анализатор и оптимизатор DDS для ArenaMW / ArenaMP. Само приложение собирается только под **Windows x64**, а профили оптимизации умеют готовить текстуры как для Windows, так и для Android/ng-gl4es.


## GitHub Actions / готовая Windows-сборка

Репозиторий содержит CI только для **Windows x64**. Каждый push в `main` собирает portable ZIP. Тег вида `v0.1.4` автоматически создаёт GitHub Release с Windows ZIP.

Portable-пакет уже содержит:

- `ArenaDDSOptimizer.exe`;
- все необходимые Qt DLL;
- **`texconv.exe` из Microsoft DirectXTex**;
- `DirectXTex-LICENSE.txt`.

Пользователю не нужно отдельно устанавливать `texconv` через `winget` и не нужно указывать его путь вручную. GitHub Actions собирает `texconv.exe` из официального DirectXTex тега `may2026`.

Подробно: [`docs/GITHUB_SETUP_RU.md`](docs/GITHUB_SETUP_RU.md).

## Что делает

- рекурсивно сканирует `.dds` во всех подпапках и подпапках внутри них, без ограничения глубины;
- читает DDS/DX10 заголовок без полной декомпрессии изображения;
- показывает размер, формат, mipmaps и размер файла;
- строит план до изменения файлов;
- вызывает `texconv` из Microsoft DirectXTex для реального ресайза, mipmap generation и BC-compression;
- сохраняет полную относительную структуру подпапок в выходной папке и backup;
- автоматически исключает `_ArenaDDS_Backup` и отдельную выходную папку, если она расположена внутри исходной;
- при оптимизации «на месте» создаёт резервную копию в `_ArenaDDS_Backup/<дата-время>`;
- заменяет исходный файл через `QSaveFile`, а не пишет поверх него напрямую;
- хранит настройки интерфейса через `QSettings`;
- умеет режим «Только анализ».
- умеет уменьшать разрешение **по меньшей стороне** до 256 / 512 / 1024 / 2048 с сохранением пропорций и без апскейла;
- по умолчанию полностью пропускает маленькие DDS (меньшая сторона ≤256);
- поддерживает редактируемый список исключений по имени/пути, например `menu`, `tx_scroll`, `icons`, `gui`, `hud`, `cursor`, `font`.

В готовой Windows portable-сборке **`texconv.exe` уже находится рядом с `ArenaDDSOptimizer.exe`**. Программа автоматически выбирает эту встроенную копию. Поле выбора пути оставлено только как резервный вариант для разработчика или ручной замены версии DirectXTex.

В исходный Git-репозиторий готовый чужой бинарник не коммитится: workflow собирает `texconv` из официального Microsoft DirectXTex (`may2026`) и добавляет его в релиз вместе с MIT-лицензией.

## Профили

### Windows + Android — безопасный (рекомендуется)

- максимум: 4096 px по большей стороне;
- непрозрачные/старые DXT1 → DXT1 / BC1;
- текстуры с альфа-каналом, GUI и normal-map → DXT5 / BC3;
- DXT3 → DXT5;
- полный mip-chain;
- BC4/BC5/BC6H/BC7 автоматически **не переинтерпретируются**: приложение помечает их «Проверить вручную».

Это сделано намеренно: BC4/BC5 могут использоваться как shader-specific одноканальные/двухканальные данные, а без знания конкретного материала автоматическая конверсия может изменить смысл каналов.

### Android / ng-gl4es — производительность

То же семейство DXT1/DXT5, но максимум 2048 px. Подходит для мобильного пакета текстур, когда важнее память и upload bandwidth.

### Windows — качество

Максимум 8192 px, но по умолчанию также остаётся в DXT1/DXT5 ради совместимости с вашей старой OpenMW/TES3MP-базой.

### Windows — BC7 (расширенный)

Перекодирует обрабатываемые текстуры в BC7. **Не используйте этот профиль для общего Windows+Android набора.** Перед включением проверьте конкретный OpenGL-драйвер/рендерер вашей ветки.

## Почему mipmaps включены

Полный mip-chain уменьшает shimmering и sampling cost на удалённых объектах. Для игровых world-textures mipmaps почти всегда выгоднее, чем DDS только с уровнем 0.

## Normal maps

Имена вида:

- `*_n.dds`
- `*_nm.dds`
- `*_normal.dds`
- содержащие `normal`

распознаются как normal-map. В совместимом профиле они планируются в DXT5/BC3, а не BC1.

## Важное ограничение alpha detection

DDS-header сообщает формат, но не всегда позволяет без декодирования понять, реально ли используются alpha-пиксели. Поэтому оптимизатор действует консервативно:

- существующие DXT5/DXT3 и RGBA считаются alpha-capable;
- GUI/icons/HUD и normal maps считаются alpha-sensitive;
- DXT1 сохраняется DXT1.

Это снижает риск разрушить прозрачность при массовой обработке.

## Сборка Windows

Требования для локальной сборки:

- Windows 10/11 x64;
- Visual Studio 2022 Build Tools / MSVC;
- CMake 3.21+ и Ninja;
- Git;
- PowerShell 7 (`pwsh`);
- Qt 6.x Widgets (CI использует Qt 6.8.3).

Самый простой вариант:

```bat
BUILD_WINDOWS.bat
```

Скрипт сначала клонирует и собирает официальный DirectXTex `may2026` (`texconv.exe`), затем собирает Arena DDS Optimizer и создаёт `package\windows`.

## Рекомендуемый workflow для ArenaMP/ArenaMW

1. Сделайте отдельную копию `Data Files/Textures`.
2. В Arena DDS Optimizer выберите профиль `Windows + Android — безопасный`.
3. Нажмите `Сканировать`.
4. Просмотрите строки `Проверить вручную`.
5. Сначала оптимизируйте в **отдельную выходную папку**.
6. Протестируйте текстуры на Windows и Android.
7. После проверки можно упаковать результат в ваш `ArenaMP - Assets.bsa` через Y056 BSA packer.

Для отдельного мобильного texture pack можно повторно обработать исходники профилем `Android / ng-gl4es — производительность`.

## Что специально НЕ делает версия 0.1

- не пытается угадывать semantic usage BC4/BC5 по содержимому shader'ов;
- не меняет UV или материалы;
- не трогает NIF;
- не удаляет текстуры автоматически;
- не требует отдельно установленного `texconv`: Windows release включает `texconv.exe`, собранный CI из официального DirectXTex;
- не пытается оптимизировать уже сжатый DDS через JPEG/PNG-подобное сжатие.

Следующий логичный этап — чтение NIF/material references для точного определения diffuse/normal/mask и автоматического выбора формата по реальному использованию текстуры.


### О дополнительной компрессии

BC1/BC3 — форматы с фиксированным размером блока, поэтому нельзя получить меньший DDS простым повышением «уровня сжатия». Режимы **Сильная** и **Максимальная** уменьшают только слишком крупные текстуры до более низкого лимита разрешения, сохраняют полный mip-chain и используют DirectXTex dithering для BC1/BC3. Перед запуском приложение показывает предупреждение.


### Изменение разрешения

При выборе `Меньшая сторона → 256/512/1024/2048` разрешение меняется **только по меньшей стороне**. Если меньшая сторона уже равна или меньше цели, DDS не ресайзится. В этом режиме лимит большой стороны профиля не выполняет дополнительный ресайз. Правила `menu`, `tx_scroll` и защита маленьких текстур запрещают только изменение разрешения, но не мешают нужной конвертации формата или генерации mipmaps.
